〇、方法学与诚实声明
- 战报来源
  - 17 队（8 T0 基准 + 9 T1）全混战；针对 7 类代表性配对，双向 × 60 种子扫描。
  - 每种配对按「最具说明性」原则挑选一场：决定胜负场取兵力差最大者，平局场取双方存活和最大者。
  - 所以本篇每场都是**单场决定性战报**（精读样本），不是概率均值——专门用来「看见」规律如何在一局里发生。
- 指标口径
  - 伤害/承伤/物理/谋略/爆发%/控制/续航：单场双方总和。
  - 「增伤活跃度」「减伤活跃度」：单场口径 = （全程 caused+taken 增伤归因之和 / 8）与（全程 reduce 之和 / 8），用于看单局厚薄；与《时序联动分析》里「80 种子平均」不是同一口径，数值会偏高，仅作单局相对比较。
  - 兵力线取每回合 round_end 快照；伤害事件列出 ≥1500 的单笔并标注增减伤栈。
- 诚实边界
  - 单场样本有随机性，结论以「规律是否在该局被肉眼看见」为准；概率层结论仍以两份论证报告（10880 场 / 10240 场）为准。
  - 始计时序结论在 v2 已用 2560 场硬编码，本篇第 7 组是在完整战报里**复现**它，不是新测。

① 定律1 · 增伤引擎分水岭（祝融张辽曹操 vs 荀彧张春华曹操）
- 阵容画像
  - 祝融侧：祝融夫人(火兽冲锋+并进+疾击其后)、张辽(其疾如风+长兵方阵)、曹操(浑水摸鱼+大赏三军)。增伤引擎=火兽冲锋+大赏三军+神兵类叠层。

- 关键事件序列
  - R1：祝融火兽冲锋 OK；张辽其疾如风/长兵方阵叠 combo+split；曹操浑水摸鱼给荀彧/张春华上 hesitation（犹豫）。

  - R4–R6：荀彧的众谋不懈/驱虎吞狼/激水之疾连续 X（发动失败，被混乱/犹豫压制），全程谋略输出几乎为零。
  - R7：荀彧侧末兵 [0,0,0]，祝融侧 [8587,8026,8234] 基本满血。
- 规律印证：同一梯队（都是 T0 基准）、同框「大赏神兵」体系，但**增伤引擎有没有真正叠起来**（祝融 3.47 vs 荀彧 0）直接造成 27775 vs 2153 的 13 倍伤害差。增伤引擎是 T0 内部的真实分水岭，标签「T0」不保证增伤在线。

② 定律2 · 爆发窗口 vs 减伤续航（祝融张辽曹操 vs 张春华乐进于禁）
- 阵容画像
  - 祝融侧：同上，增伤4.59、爆发81.8%（前3回合吃掉 81.8% 总伤）。
  - 张春华乐进于禁侧：减伤2.29（乐进 damage_reduce 0.6 + 于禁 0.5，持续全局）、续航4425（张春华 heal）、增伤0.04（几乎无）。典型「减伤+续航拖局」乌龟流。
- 关键事件序列
  - R0：乐进/于禁 已上 damage_reduce（减伤盾先于开战就立起）。
  - R1：祝融 → 乐进 -2029，增伤栈 = 火兽+80% / 大赏+49% / 火兽+160% / 兵种+18% / 百战无怯-20%；同回合张春华的迷阵/落雷全部 X（被曹操浑水犹豫压制，控链没上线）。
  - R2：乐进中军 1380→0 被清零；张春华强势 OK 但只是降伤 debuff。
  - R3–R5：张春华持续迷阵/落雷 X，减伤盾虽在但扛不住前3回合叠加增伤的爆发；于禁大营也被压到 119。
  - R6：张春华乐进于禁侧 [0,0,0] 全灭。
- 规律印证：减伤+续航**是**把增伤转化为胜率的两条出路之一，但它**赢不了「增伤开窗更早更厚」的对手**。张春华侧的减伤盾（2.29）厚度其实高于祝融的增伤（4.59 是单局口径偏高），但祝融爆发窗在 R1 就砸穿、且张春华自己的控链被犹豫锁死——**爆发路线的胜负手是「先于对方控链/减伤生效前把人打死」**。这正是定律2「爆发窗口」出口的实战样貌。

三、7 份战报对全部规律的验证结论
- 规律1（增伤引擎分水岭）：① ⑦ 双证——同梯队内增伤在线(3.47/4.05) vs 离线(0/0.06)，伤害差 13 倍/9 倍。
- 规律2（爆发 vs 减伤续航）：② 证——减伤盾(2.29) 扛不住前3回合增伤爆发(4.59,爆发81.8%)；④ 证其反面——双拖局则互相抵消成平。
- 规律3（纯控制/减伤缺失陷阱）：③ 证——控制7 但增伤0.11/减伤0.23，伤1657 被反杀；窗口≠杀伤。
- 规律4（平局=8回合上限+双存活）：④ 证——双减伤+双续航，R8 双存活判平。
- 规律5（伤害类型DNA）：⑤ 证——纯物理26236 vs 纯谋略3243，但受减伤(0.9/0.49)与兵种克制调制。
- 始计时序结论（v2）：⑦ 复现——太史慈 R1 始计 0% 接通，始计「有但没接上」。
- 诚实披露（梯队非全局）：⑥ 证——增伤0的T0(太史慈关羽) 被增伤成型的T1(曹彰) 全灭，维度 > 标签。
- 一句话收口：**所有规律的真正共同根因只有一个——增伤引擎的「有无 / 厚薄 / 开窗位置 / 时序接通」**。它决定了伤害能不能从「开了窗」变成「打穿人」；控制、减伤、续航都是它的放大器或替代出口，但谁也替代不了增伤引擎本身。

四、复现与文件清单
- `docs/t0t1_reports.json` —— 7 组代表性战报完整事件流（阵容画像 + 双方底层维度 + 逐回合兵力线 + 全事件）。
- `scripts/t0t1_reports.mts` —— 复现：`SEEDS=60 npx tsx scripts/t0t1_reports.mts`。
- `scripts/_dump_reports.cjs` —— 把 JSON 导出为可读逐回合时间线：`node scripts/_dump_reports.cjs` → `docs/_tl_dump.txt`。
- 引擎底层接口：`runBattle` 返回 `BattleReport.events`（round_start / skill_trigger / attack_hit / damage / status_inflicted / heal / round_end / battle_end），`DamageModifiers.caused/taken/reduce` 提供逐笔增减伤归因——已证实可支撑单局精读级验证。
